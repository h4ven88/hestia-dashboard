# Hestia v1.6.5 Release Notes

**Release Date:** 2026-09-09

---

## What's new in v1.6.5

- **Activity Log can now be searched, filtered, and paged back through** — no longer capped at the most recent 25 events.
- **Push notifications now cover arming and disarming**, not just an active alarm — a new toggle mirrors what Announcements has always spoken out loud. **Requires updating `HestiaDashboard.groovy`.**
- **Athena and Routines now confirm a command actually worked before reporting success** — no more "Done" spoken before the hub has actually accepted it.
- **Motion (and smoke/water/lock/contact) announcements no longer repeat themselves** — "Motion detected in the Motion Detector Loft" is now "Motion detected in the Loft."

See below for full details on these and everything else that's landed since v1.6.4's initial Diagnostics & Activity Log release — mostly hardening and reliability work from a full pre-native-wrapper security and reliability audit, none of which had been formally announced until now.

---

## Connection Diagnostics & Activity Log

A new Settings section for figuring out what's actually going on when something isn't working, instead of guessing.

**Settings > Diagnostics — 8 on-demand connection checks:**

- **Hub Reachability** — can this device reach your Hubitat hub directly.
- **HTTPS / Mixed Content** — flags when this page's HTTPS origin conflicts with an HTTP hub URL, and whether that's actually blocking anything.
- **Maker API Credentials** — whether your App ID and access token are being accepted.
- **Hub Login Security** — detects a login page intercepting API requests instead of returning real data.
- **Companion App** — reachability and version of the Hestia app on your hub.
- **Push Pipeline** — notification permission, service worker, and device registration state.
- **Cloud Sync** — reachability of the hestari.com backend.
- **Browser / Environment** — browser, online state, and API support on this device.

Each check runs independently, so a slow or failing one never blocks the others from reporting.

**Send Test Notification** — a manual button to confirm push delivery actually works right now, without waiting for a real device event.

**Activity Log** — a running record of device events (doors, windows, locks, motion, smoke/CO, water, alarm arm/disarm) captured server-side, independent of your notification settings. Turning on either Push Notifications or Announcements is what populates it — it shows what happened in your home, not just what you chose to be notified about.

## Real bugs fixed along the way

- **Fixed a boot hang on HTTPS + HTTP-only hub setups.** hestari.com could spin forever with nothing loading — lights stuck at 0, weather stuck on "Fetching...", climate stuck on "--". Root cause: a request the dashboard makes during boot could sit indefinitely without failing or succeeding when the page (HTTPS) requests a resource from a plain HTTP hub (a mixed-content browser restriction), and that request had no timeout — so the whole boot sequence just waited forever. Every request on that path now times out and moves on instead of hanging.
- **Fixed a device staying flagged as "removed from Maker API" after being dismissed.** Dismissing it correctly cleared it from Rooms & Devices, but if it was also registered as an Artemis sensor (contact, motion, smoke, or water), clicking **Save & Apply** afterward silently pulled it right back in — Save & Apply rebuilds the internal device list from scratch, and the leftover Artemis sensor entry was enough to reintroduce it. An earlier attempt at this fix addressed a narrower refresh-timing race; this is the actual mechanism, and dismissing now clears the device from Artemis sensors too.
- **Reduced Activity Log write volume for motion.** Every motion "active" event wrote a new Activity Log entry, even while push notifications for it were off — a lingering person could retrigger the same sensor dozens of times in a few minutes, each one a separate write. Motion now gets a 10-minute per-sensor cooldown while the system is disarmed, so routine daily activity doesn't flood the log. While armed, every motion event still logs at full resolution — that's exactly when tracking movement matters most.
- **Hardened output escaping** across device, room, camera, reminder, and routine names throughout the dashboard UI.
- **Fixed an Activity Log crash and history-accuracy bug** that could surface under normal day-to-day usage — the log could stop loading or, in some cases, show older events instead of the most recent ones. Both are now fixed and verified.
- **Improved push notification delivery reliability** so a single device with a connection issue can no longer delay or block notifications to the rest of the household.

## Additional hardening

A further pass through the same review, closing out the lower-risk findings.

- **Artemis PIN lockout now survives a reload.** The 5-attempt lockout used to reset if the page refreshed mid-lockout; it's now remembered until the timer actually runs out.
- **Settings PIN now has the same lockout** — previously unlimited attempts. Both PINs are unaffected if you've never set one.
- **Backup/export and Factory Reset now cover every setting.** Push Notifications, Announcements, Reminders, Routines, room sort order, temperature unit, and companion-app credentials were silently missing from both — a backup taken before a factory reset or device migration didn't actually have everything back. Factory Reset also now clears cameras, locks, and your Settings PIN, which it previously left behind despite the confirmation saying otherwise.
- **Athena now speaks when a routine finishes or a command fails**, instead of only showing it on screen — useful any time you're not looking at the panel.
- **Camera tiles no longer get stuck** if a snapshot request hangs instead of failing outright — they now time out and show Offline like any other failure.
- **Fixed a status display bug** where an unexpected value from your hub's alarm system could show "Disarmed" even while actually armed. It now leaves the last known state alone instead of guessing.
- **Fixed a status-dot color bug** — two status indicators were rendering fully invisible due to an undefined color variable, and roughly 30 other status colors weren't adjusting for your selected theme like the rest of the app does.
- **Removed a leftover, unused backend endpoint** that had no authentication and wasn't referenced anywhere in the app.
- Smaller backend reliability fixes: a long-running armed state can no longer silently expire and go quiet on "armed only" notifications, and two device-registration requests arriving at nearly the same moment (e.g. two devices subscribing to push at once) can no longer silently overwrite each other.

## Further hardening

- **Weather no longer gets stuck on "Fetching weather..." forever** if you skipped setting a location — it now tells you to set one in Settings.
- **Voice commands time out instead of hanging.** If Claude, Google Speech-to-Text, or Google Text-to-Speech doesn't respond, the panel now fails fast with a clear message instead of getting stuck indefinitely.
- **Camera tiles show "Checking..." while first loading**, instead of briefly looking online before the real status is known.
- **Camera snapshot/stream URLs are now checked for a valid web address** when you save Settings, so a typo doesn't silently fail with no explanation.
- **Diagnostics now tells you when notifications are blocked in your browser settings**, separately from "not yet asked" — these need different fixes, and now say so.
- **The Activity Log now distinguishes a real server problem from being offline**, instead of showing the same generic error for both.
- **Importing a backup now warns you if it included push notification registrations** that can't actually carry over to the new device.
- Backend hardening: every server endpoint now returns a proper error response instead of a generic failure page if something unexpected goes wrong, and the config sync endpoint now rejects malformed data before storing it.
- Several small accessibility and consistency fixes: icon-only close buttons are now properly labeled for screen readers, and a handful of icons/buttons that weren't fully adapting to your selected theme now do.

## Wake detection, testing, and validation improvements

- **Athena now notices if she loses microphone access while listening for the wake word** — a permission revoked mid-session, or an input device disconnecting, used to leave wake detection silently dead until you reloaded the page. She now shows a clear warning on her floating button and tries once on her own to reconnect.
- **Camera settings now have a "Test connection" button** so you can confirm a snapshot or stream URL actually works before saving, instead of finding out later from a blank tile.
- **Diagnostics has a new check for the single most common real-world misconfiguration**: a device referenced somewhere in Hestia (a room, a lock, an Artemis sensor) that was never actually authorized in your Maker API app instance. Previously every other check could show green while that device just quietly never responded.
- **Wall Panel setup now warns you if no Settings PIN is set** before you deploy an always-on display — without one, anyone standing in front of the panel can open and change Settings.
- **Voice-created routines now check that every device actually exists** at the moment you create them, instead of silently failing the first time the routine runs — Athena will tell you right away if she couldn't find something.
- **Reassigning an Artemis sensor's type now warns you if the device's real capabilities don't match** what you just chose, without blocking the change.
- **"Send Test Notification" can now target one specific device** instead of always notifying every registered device at once, making it much easier to track down which device isn't receiving pushes in a multi-device household.

## Companion app: retry on failure and a real truncation check

- **Arm-state and alarm push notifications now retry once** if the initial delivery attempt fails. A momentary network hiccup at the exact moment of a real alarm previously meant that notification just never went out. Confirmed working against a real hub.
- **Fixed a diagnostic check that could never actually detect a stuck config.** The check itself never worked correctly since it was added; it's now wired up to actually catch this if it happens.

## Push registration self-healing

- **Fixed a device silently falling out of push registration over time**, showing as registered in Settings and Diagnostics while never actually receiving notifications. Devices are periodically dropped from the notification service for normal reasons (an old registration expiring); this device now automatically re-confirms itself with the server every time you open the dashboard, instead of only if you disable and re-enable push manually.
- **Settings → Push Notifications now tells you when your browser itself has revoked notification permission**, even though this device still shows as "registered." This is the exact situation that made a device stop receiving pushes with no visible explanation — the automatic self-healing above only works when notification permission is actually granted, so if your browser's permission has reverted, nothing could fix it without you noticing. A one-click "Re-enable notifications" button is now shown right there.

## Fixed a runaway background retry loop

If Athena's wake-word listener falls back to your browser's built-in speech recognition (which happens when the primary engine can't start) and microphone access is denied, it used to retry every 300ms, forever, with no way to stop on its own. It now gives up after 3 tries and shows the same clear warning used elsewhere for lost microphone access.

## Fixed the "settings changed on another device" banner firing on your own edits

Saving settings on a device could trigger its own "Settings changed on another device — Refresh" banner a little while later, even though nothing else had touched the config. If the screen then sat idle for 30 seconds, the page would silently reload itself in the background. Both were caused by the same tab losing track of the fact that its own just-saved change was, in fact, its own. Fixed: saving now correctly marks its own change as already accounted for, so the banner and auto-refresh are reserved for real cross-device changes going forward.

## Reminders now handle Daylight Saving Time correctly, and Athena speaks up sooner

- **Fixed a rare but real bug in recurring reminders**: a daily/weekly/monthly reminder scheduled for a time inside the one-hour window that shifts on Daylight Saving Time changeover days (the skipped hour each spring, the repeated hour each fall) could fire at the wrong time, twice a year. Verified against synthetic dates covering both 2026 transitions, a no-DST location, and a Southern Hemisphere location before shipping.
- **Athena now speaks up if she's not hearing you clearly.** In a noisy room, or if you're speaking softly, she used to just keep listening in silence for the full 15 seconds before giving up. She now shows "Still listening — try speaking a bit louder" after a few seconds of not picking up clear speech.

## Activity Log can now be searched, filtered, and paged back through

Settings → Diagnostics → Activity Log used to show only the most recent 25 events with no way to see anything older. It now has a category filter, a text search box, and a "Load more" button that fetches genuinely older history instead of re-showing the same page.

## Push notifications for arming and disarming, not just an active alarm

Announcements has always spoken every arm/disarm step out loud — "Arming Away," "Armed Home," "Disarmed" — but Push had no equivalent at all; its only security notification was for an actual intrusion trip. There's now a matching **Arm/Disarm Status** toggle in Settings → Push Notifications that covers every one of those same steps, so your phone can get the same heads-up your Ring integration already gives with its arming chime — including the exit-delay countdown starting, not just the final armed state. **Requires updating `HestiaDashboard.groovy`.**

## Athena and Routines now confirm a command actually worked before saying so

Athena used to say "Done" the instant she sent a command to your hub, regardless of whether the hub actually accepted it — since she's meant to be used hands-free, that meant a rejected command could sound identical to a successful one. She now waits for real confirmation from the hub before speaking, and says so plainly if something didn't go through instead. Routines had the same gap one level down — a routine's "3 done, 1 failed" summary could actually be inflated even when a step failed; it now only counts a step as done once the hub has actually confirmed it.

## Motion announcements no longer repeat themselves

If a sensor is named something like "Motion Detector Loft," Athena used to announce "Motion detected in the Motion Detector Loft" — awkward and repetitive. Announcements now strip that kind of redundant wording automatically, so the same sensor now announces "Motion detected in the Loft." Applies to smoke, water, freeze, lock, and contact announcements too, not just motion.

## Security, consistency, and Locks device picker (2026-09-09)

- **Per-install PIN salt.** Both the Artemis disarm PIN and Settings PIN were hashed with a single salt identical across every Hestia install — anyone could precompute a table once and reuse it against any install. Now combines that with a random per-install salt; existing PINs upgrade transparently the next time you enter them correctly, with no forced re-prompt.
- **Settings → Door Locks now has a real device picker.** "+ Add Lock" used to leave a blank text field for you to hand-type a numeric Hubitat device ID. It now shows a dropdown of your hub's actual lock-capable devices, the same way Announcements' motion-sensor picker already works. Already-configured locks display their linked device without letting you accidentally retype it.
- **Activity Log can now be exported to CSV**, matching whatever the category filter/search currently narrows the list to.
- **Athena's voice-panel helix animation now matches your selected theme's amber** — it previously always showed the Dark theme's shade regardless of which theme you'd picked.

## Camera tiles now show a real reason when offline, where it's safely knowable (2026-09-10)

A camera going offline used to always show the same generic "Offline" badge, whether it was a bad URL, a login issue, or your network being down. It now shows the actual reason when one can be determined safely (not found, unauthorized, mixed content, a non-image response) — some failures genuinely can't be distinguished from a browser without risking breaking cameras that work fine today, so those still show "Offline" rather than guessing.

## Hub URL reverting to HTTP, and a camera count fixed (2026-09-10)

- **Fixed the HTTPS hub URL (`:8443`) silently reverting to HTTP.** If you followed the app's own hint to switch your hub URL to `https://<hub-ip>:8443` for encrypted lock/disarm commands, it could silently revert back to `http://` on the next config load, followed by "Hub unreachable — showing last known state." A safety guard from several months back (written for a different, unrelated bug involving a bare HTTPS URL with no port) was too broad and stripped a correctly-specified `:8443` along with it. It now only strips the exact pattern it was meant to catch, leaving a deliberately-set `:8443` alone. If you hit this, your hub URL should now save and stay saved correctly.
- **Fixed the Cameras sidebar entry showing "0 of N online" on every fresh load**, correcting itself only after you clicked into the Cameras view once. Camera status is now checked in the background right after the dashboard loads, so the sidebar count is accurate from the start.

## Entry-delay countdown fixed — it wasn't showing at all, and could send a false alarm push (2026-09-11)

If a monitored door opened while armed, the 60-second countdown before an intrusion alert actually escalates was never displayed on screen, and the push notification said "Security Alarm triggered!" the instant the countdown *started* rather than once it actually escalated. Both are fixed:

- The push now says something like "Alarming in 60 seconds — disarm to cancel" during the countdown, and only says a real alarm was triggered once it genuinely escalates.
- The on-screen countdown ring now actually appears. Root cause was a background sync that runs every ~10 seconds to keep arm/disarm state accurate — it had no way to tell "a countdown is legitimately still running" from "nothing new happened," so it was clearing the countdown within about 10 seconds of it starting, every time. Exit-delay (the countdown when arming away) was never affected, since that has its own distinct status the sync already recognized.
- Two smaller related bugs fixed along the way: if you'd previously opened the nested camera view inside Security without backing out, a later countdown would render into that stale view instead of showing; and the full red "Intrusion detected" banner was appearing during the calm countdown phase, not just on a real trip.

## Fixed a stale companion-app ID silently flooding Hubitat's own logs (2026-09-12)

If Hestia's companion app on your hub was ever uninstalled and reinstalled, the new instance gets a new ID — but the dashboard had no way to notice its cached copy of the old ID had gone stale while accessed via hestari.com (rediscovering it live requires loading directly from the hub, which hestari.com can't do due to a browser cross-origin restriction). The result: a background check that runs every 30 seconds kept quietly retrying that same dead ID, and your hub logged a warning each time — a slow, continuous flood with no obvious cause. It now recognizes when the hub reports that ID doesn't exist anymore and clears it immediately instead of retrying forever. If you still see stale credentials afterward, loading the dashboard once directly from your hub's own address will refresh it with the current one.

## Notes

- **This release includes Groovy changes** — re-paste the latest `HestiaDashboard.groovy` (or update via Hubitat Package Manager) to get the arm-state push retry, the config-truncation check, the arm/disarm status push notifications, and the corrected entry-delay push wording. If you're not on Hubitat Package Manager, get the latest from [GitHub](https://github.com/h4ven88/hestia-dashboard/blob/main/HestiaDashboard.groovy).
- One architectural item — the cloud-sync trust model — was deliberately deferred out of this pass; it's a bigger design conversation, not a quick patch, and low realistic risk at the current scale.
