# Hestia v2.0.2 Release Notes

**Release Date:** 2026-09-29

---

## Take this one

This fixes a bug we introduced in v2.0.0 that could replace your settings on every device in your home. If you run a wall panel, a tablet, or anything that sometimes cannot reach your hub, it could affect you.

Nobody did anything wrong to trigger it. It was our regression.

---

## What was happening

v2.0.0 encrypted your synced settings with a key belonging to your household. That was the point of the release, and it fixed a real problem: before it, anyone sharing your public IP address could read your settings.

What we did not account for is that the old, weak key was also how a device **bootstrapped itself**. A device with no settings of its own used to be able to read the household record straight from the cloud and configure itself. After v2.0.0 it needs the household key, and the key comes from your hub.

So a device that cannot reach your hub had no way in. Hestia looked at it, saw no settings locally and nothing it could read from the cloud, and concluded it must be a brand-new household. **It showed the setup wizard.**

That is where it turned bad. Completing the wizard rebuilds your rooms from scratch and saves, which creates a *new* household key and rewrites the stored record under it. Every other device in your home still holds the old key, so none of them can read the record any more, and the next one to look also gets shown the wizard. One device starting fresh takes the household with it.

The tell was Settings, Diagnostics, Cloud Sync reading **"Record present but unreadable"**.

---

## What changed

**Hestia now tells the difference between "a new household" and "an existing household this device cannot read".** They look identical from the device's own storage, which is exactly why this went wrong.

When it finds settings it cannot read, it no longer offers the wizard. It shows a screen explaining the situation and naming the one thing that fixes it: **open Hestia on a device that still works, go to Settings, Wall Panel, and open that link on the stuck device.** That link carries the household key across. Connecting the device to your home network where it can reach your hub does the same thing.

It is deliberately cautious in the other direction. If the backend is unreachable, or there is genuinely no stored record, or the record is an older one it can still read, it goes to the normal wizard. **A real first-time setup is never blocked.** There is also a confirmed "set up as a new household anyway" option for the genuine case of a second home on a shared address, behind a warning that says plainly what it costs.

**The Diagnostics message is rewritten.** It used to lead with "belongs to a different household sharing this public address" — alarming, usually wrong, and with nothing you could act on. At least one person read it and reasonably concluded their settings were gone. It now leads with the explanation that is nearly always the real one, and tells you how to recover.

---

## Already stuck?

You do not need this update to recover, though you should take it.

**Open Hestia on a device that still works**, go to **Settings, Wall Panel**, and open that link on the device that is stuck. It carries your household key.

If no device works any more, set one up against your hub on your home network first. That device can then hand the key to the rest.

---

## Also in this release

**The update instructions were wrong and are corrected.** We said to open the Hestia app and click Done. Use the **⬇ Update Dashboard File** button instead.

Done runs a *conditional* download: it checks the published version first, skips if it believes you are already current, and gives up silently if that check times out. So it can appear to work while leaving your hub on the old dashboard. The button forces the download every time.

---

## Updating

1. **Companion app.** HPM, or paste `HestiaDashboard.groovy` over Apps Code → Hestia Dashboard and Save.
2. **Open the Hestia app and click ⬇ Update Dashboard File.**
3. **The dashboard.** On hestari.com, reload. Served from your hub, it arrives at step 2.
4. **Check it.** Settings, Diagnostics, Run all checks. Companion App should read green "v2.0.2 (up to date)".

The companion app's code is unchanged in this release; only its version moved, so it stays in step with the dashboard.

## For the technically inclined

The failing path was `cloudSyncDiscover()` returning null for a device holding no household secret, because the legacy IP-derived key cannot decrypt a migrated record. `needsOnboarding()` then saw empty local storage and returned true. `obFinish()` does `rooms.length = 0`, rebuilds, and calls `saveConfig()`, which mints a secret and republishes — the cascade.

Boot now calls a check before offering the wizard, and that check fails open on every ambiguity so first-time setup cannot be blocked by a network hiccup.

Worth recording: the first attempt at this fix passed a full green test suite while doing nothing whatsoever. It passed an options object where the fetch helper expects a timeout in milliseconds, so every request aborted immediately and the guard silently failed open on every device. The unit test stubbed that helper with the wrong argument order and cheerfully agreed with itself. It was caught only by serving a real encrypted record and driving an actual page load. The stub now validates its own contract, and reinstating the original argument order fails the suite.
