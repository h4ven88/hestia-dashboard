# Hestia v1.6.0 Release Notes

**Release Date:** 2026-08-17

---

## New: Cameras

A new Cameras module, configured in **Settings → Cameras**.

### How it works
- Add a camera by giving it a name, room, and a **snapshot URL** -- any URL that returns a still image (JPEG/PNG/SVG) when fetched. Hestia doesn't care which integration or brand produced it; it just displays whatever comes back.
- Manual reorder via up/down buttons in Settings controls display order everywhere cameras appear (no drag-and-drop -- consistent with how room ordering already works).
- **Desktop/tablet:** a new sidebar entry between Lights and Security, and a dedicated view showing up to 4 snapshots at once in a grid, with pagination for more. Per-camera refresh, an expand-to-detail view, "Refresh all," and a 30-second auto-refresh while the view is open.
- **Mobile:** no new bottom tab (keeps the bar at 5). Cameras nests inside the existing Security tab as a summary row ("N · M online"), tapping through to a scrollable list of real thumbnails.
- Snapshots are fetched with a cache-busting parameter each refresh, since browsers cache static image URLs by default.

### A note on Ring cameras specifically
Hubitat's *official* Ring integration does not expose any snapshot capability. Ring snapshots are achievable today through Hubitat's built-in Dashboard app tile-image endpoint (`/apps/api/<dashboardAppId>/snapshot/RING||<deviceId>?access_token=...`), which works from the *unofficial* Ring integration's device entries even when they don't fully register as visible child devices elsewhere. No extra infrastructure (go2rtc, bridges) required for this path.

### If a camera shows "Offline" but the URL works in a browser tab
This is very likely a mixed-content issue: hestari.com is served over HTTPS, but most local camera/hub URLs are HTTP. If your hub also serves HTTPS locally (most Hubitat hubs do, with a self-signed certificate), switching the snapshot URL to `https://` and visiting that URL directly once to accept the certificate warning resolves it -- the same fix already recommended for the hub connection itself in the "Hub connection is using HTTP" banner.
