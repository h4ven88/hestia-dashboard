# v2.0.2 forum post

**v2.0.2 is up, and this one is worth taking promptly. It fixes a bug I introduced in v2.0.0 that could wipe your settings across every device in your home.**

@jbwrd3 found it the hard way over the last couple of days. Nothing he did caused it, and I want to say that plainly before anything else.

## What was going wrong

v2.0.0 started encrypting your synced settings with a key that belongs to your household. That fixed a real problem, because before it anyone sharing your public IP could read them.

What I missed is that the old weak key was also how a device **bootstrapped itself**. A device with nothing stored locally used to read the household record straight from the cloud and set itself up. After v2.0.0 it needs the household key, and that key comes from your hub.

So a device that could not reach the hub had no way in. Hestia saw nothing stored locally, nothing it could read from the cloud, and concluded it must be a brand new household. **It showed the setup wizard.**

That is the damaging part. Finishing the wizard rebuilds your rooms from scratch and saves, which creates a *new* household key and rewrites the stored record under it. Every other device still holds the old key, so none of them can read it any more, and the next one to look also gets the wizard. One device starting fresh takes the whole household with it.

The giveaway was Diagnostics showing **"Record present but unreadable"**.

## What it does now

Hestia now tells the difference between "a new household" and "an existing household this device cannot read". They look identical from the device's own storage, which is precisely why this went wrong.

When it finds settings it cannot read, it no longer offers the wizard. It explains the situation and names the fix: **open Hestia on a device that still works, go to Settings → Wall Panel, and open that link on the stuck device.** That link carries the household key across. Connecting the device to your home network so it can reach your hub does the same thing.

It is cautious the other way too. Unreachable backend, no stored record, or an older record it can still read all go to the normal wizard, so a genuine first-time setup is never blocked. There is a confirmed "set up as a new household anyway" for the real case of a second home on a shared address.

I also rewrote that Diagnostics message. It used to lead with "belongs to a different household sharing this public address", which is alarming, usually wrong, and gives you nothing to do. It now leads with the explanation that is nearly always the real one, and tells you how to recover.

## Already stuck?

You do not need the update to get back, though do take it.

**Open Hestia on a device that still works → Settings → Wall Panel → open that link on the stuck device.** It carries your key.

If nothing works any more, set one device up against your hub on your home network first, then use its Wall Panel link for the rest.

## One correction

My update instructions were wrong. I said to open the Hestia app and click Done. Use the **⬇ Update Dashboard File** button instead.

Done runs a conditional download: it checks the version first, skips if it thinks you are current, and gives up silently if that check times out. So it can look like it worked while leaving your hub on the old dashboard. The button forces it every time.

Sequence: paste the Groovy into Apps Code → Save → open the Hestia app → **⬇ Update Dashboard File** → reload the dashboard. Then Settings → Diagnostics → Run all checks should show Companion App green at v2.0.2.
