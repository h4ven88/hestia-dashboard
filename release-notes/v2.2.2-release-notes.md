# Hestia v2.2.2 Release Notes

**Release Date:** 2026-10-23

There is an Android app, and it can be installed. Everything else in this
release is a layout or wording fix found while getting it ready.

---

## How to update

1. Copy `HestiaDashboard.groovy`, open **Apps Code**, replace the existing
   code, and **Save**.
2. Open **Apps → Hestia Dashboard** and click **⬇ Update Dashboard File**.

**Done is not required this time.** `initialize()` is unchanged in this
release, so there is no new scheduled job or subscription to register. The
Groovy itself is byte-identical to v2.2.1 apart from its two version strings,
which move in lockstep so the companion-app check in Diagnostics does not
report a mismatch.

---

## The Android app

An installable APK, at **hestari.com/install**. Android 8.0 or later.

It is not a wrapper around the website. It finds your hub itself over mDNS,
shows you the hub's certificate fingerprint and pins that exact key, and
relays every hub request over that pinned connection. Nothing is typed in
during setup: no address, no Maker API token, no app ID.

Three defects were found and fixed by running the release build on a wiped
phone rather than by reading it:

- **First contact with a hub could time out and report "No answer from that
  address" on a hub that was answering.** The shared HTTP client is tuned for
  the warm steady state, 5 seconds with no retry, and that budget was being
  used for the initial TLS handshake against a hub's self-signed certificate.
  Discovery already used a longer one. First contact now has its own.
- **The device poll built a new HTTP client per request**, so it performed a
  full TLS handshake roughly once a second and abandoned a connection pool
  each time. There was already a shared pinned client for exactly this reason
  and the camera path already used it; the busier caller never did.
- **A failure inside the native bridge was logged nowhere.** The release build
  compiles the page console out, so a problem during first run left a message
  on screen that nobody could investigate. It is logged now, with the query
  string stripped, because a hub URL carries the Maker API token in it.

Known limits, stated plainly: Fire tablets cannot run it, since Fire OS has no
Play Services. Camera snapshots served from a camera's own address rather than
through the hub are not supported yet. A force-stopped app receives no
notifications until it is reopened, which is Android's rule and not something
the app can work around.

## The hub-unreachable banner was unreadable on a phone

The banner that appears when Hestia cannot reach your hub is a sentence with a
link in the middle of it. It was laid out as a flex row, which makes each run
of text its own column, so on a phone the sentence rendered as three narrow
blocks of text sitting on top of one another.

Photographed on a real phone, which is the only way this was ever going to be
noticed: it reads correctly at desktop width.

It is a sentence now, and lays out as one.

---

## The app no longer tells you to accept a certificate

In the app, that same banner used to say "open https://your-hub, accept it,
then come back". That is correct advice in a browser and impossible in the
app: a WebView offers no way to accept a certificate, which is precisely why
the app pins the hub's key during setup instead.

App users now get advice they can act on, about the hub's power and the Wi-Fi
network. Browser users keep the certificate wording, which is still right for
them.

## hestari.com

- **An install page at `/install`**, covering Android, iOS and the browser,
  with the APK's checksum published so the download can be verified.
- **`/download`** goes straight to the current APK.
- The landing page **no longer slides sideways on a phone**. The row of
  preview tabs could not shrink below its own width, which pushed the whole
  page wider than the screen.
- Corrected three places that described Hestia as open source under Apache
  2.0. It is CC BY-NC 4.0, free for personal use, and the full source is
  public. Neither half of the old wording was accurate.
