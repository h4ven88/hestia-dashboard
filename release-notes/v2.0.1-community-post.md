# v2.0.1 forum note (follow-up post in the existing thread)

**v2.0.1 is up, right on the heels of 2.0.0. Apologies for the back to back release, but this one matters if you already updated.**

2.0.0's encryption only actually kicked in when you saved a setting. On startup the dashboard would try, find no household key yet, and quietly give up, because the key was only ever created during a settings save. So if you updated and never opened Settings, you are still on the old key, with nothing on screen telling you so.

I caught it by checking my own household's stored record after release and finding it still in the old format. Clicking Save & Apply migrated it instantly, which is what confirmed the cause.

2.0.1 creates the key on startup instead. Nothing for you to do differently.

**If you are already on 2.0.0:** either take this update, or just open Settings and hit Save & Apply. Either one fixes it. Settings, Diagnostics, Run all checks will show Cloud Sync green "Synced" once you are across.

**The companion app code did not change in this release.** Only its version number moved so it stays in step with the dashboard. Worth re-pasting anyway, otherwise Diagnostics shows amber for a version mismatch when nothing is actually wrong.

## Correction to the update steps I posted for 2.0.0

I said to open the Hestia app and click Done. Use the **⬇ Update Dashboard File** button instead, inside the app under Apps.

Done runs a *conditional* download: it checks build-info.json first and skips if it believes you are already current, and it also gives up silently if that check times out. So it can appear to work while leaving your hub on the old dashboard. The Update Dashboard File button forces the download every time.

Full sequence, which is what I run myself:

1. Copy `HestiaDashboard.groovy` from GitHub
2. Hubitat, Apps Code, open Hestia Dashboard, replace the code, Save
3. Hubitat, Apps, open Hestia Dashboard
4. Click **⬇ Update Dashboard File**
5. Open the dashboard

Clicking Done as well does no harm, and it is the only thing that re-subscribes to HSM events and reschedules the update check. It is just not what pulls the new dashboard down.
