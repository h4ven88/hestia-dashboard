**Release Date:** 2026-05-23

## Announcements

Speak device events aloud — no more manually creating announcements per device on external hubs.

### How it works
- When a device event occurs (door opens, lock unlocks, motion detected), Hestia announces it via Google Cloud TTS or browser speech synthesis.
- Announcements are triggered by WebSocket events from the Hubitat hub — zero polling, instant response.
- A 3-second per-device debounce prevents burst spam (e.g., arming triggers multiple sensor changes).
- Announcements are automatically suppressed when Athena is actively listening or speaking.

### Supported categories
- **Doors** — "Front door opened" / "Front door closed"
- **Windows** — "Kitchen window opened" / "Kitchen window closed"
- **Locks** — "Front door locked" / "Front door unlocked"
- **Motion** — "Motion detected in the garage" (select specific sensors)
- **Smoke / CO** — "Smoke detected in the hallway" / "Carbon monoxide detected in the basement"
- **Water / Freeze** — "Water detected in the laundry room" / "Freeze alert in the garage"
- **Alarm Status** — "Armed away" / "Disarmed" / "Arming away — 60 seconds starting now" / "Attention — alarm triggering in 60 seconds"

### Settings
- New **🔊 Announcements** section in Settings with global enable/disable
- Per-category toggles (all default on except Motion, which requires selecting specific sensors)
- Open/Unlock and Close/Lock event types can be toggled independently
- Motion sensor picker populated from Artemis security sensors
- Smoke/CO and Water/Freeze default to enabled given their safety-critical nature

## Bug Fixes

### Mobile intrusion delay timer
- **Fixed:** The entry-delay countdown ring was not rendering on mobile when intrusion was detected from Ring or HSM.
- **Root cause:** The WebSocket handler opened the PIN sheet without first switching to the security tab, so the countdown ring HTML was never created.
- **Fix:** Both HSM and Ring entry-delay paths now call `selectTab('security')` before `artemisOpenSheet()` on mobile.

## Local Training Pipeline

New local training infrastructure for wake word models, replacing the Google Colab workflow.

- `setup_training.py` — one-time environment setup (OpenWakeWord, Piper sample generator, background audio datasets, feature files)
- `train_local.py` — per-word training wrapper with synthetic clip generation, real clip injection, augmentation, and MLP training
- `benchmark_model.py` — side-by-side model comparison using OWW's native inference pipeline
- All compatibility patches for Python 3.14 + PyTorch 2.12 + Windows documented in project memory

### Training quality improvements
- Real negative + hard negative clips now injected into training (were completely unused before)
- Positive clips split 80/20 train/test (was all train, causing overfitting)
- Feature cache always cleared before augmentation (prevents stale data)
- Batch balance: positives 256, adversarial negatives 128, ACAV 1024
- Augmentation rounds increased from 1 to 2
- Fixed `best_val_fp` tracking bug that caused negative weight to double every sequence
