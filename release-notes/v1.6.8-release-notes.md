# Hestia v1.6.8 Release Notes

**Release Date:** 2026-09-20

---

## The exit-delay countdown now agrees with itself

Tapping Arm Away starts a countdown before the system actually arms. That part worked, but everything around it disagreed with it.

- The mode row kept **Disarm** lit for the whole countdown, while the card right above it said "Arming Away." The row was reading the armed mode, which is still "disarmed" until arming finishes, so it was technically right and completely misleading.
- The countdown in the sidebar froze at whatever second it happened to be drawn at, so it drifted further from the card the longer you watched.
- The topbar badge and the Home screen's status card stayed hidden until arming completed, so leaving the Security screen meant losing sight of the countdown entirely.

Now the mode you are arming into reads as selected, with a gentle pulse until your alarm system confirms it, and the card, sidebar, topbar and Home screen all show the same ticking countdown.

## "Hub unreachable" now tells you what to try

That banner used to say the same sentence no matter what was wrong. A browser genuinely cannot tell an untrusted certificate apart from an unplugged hub, so Hestia now names the most likely cause for how your hub is set up.

- **Hub address starts with `https://`:** the usual cause is that this particular device has never accepted the hub's certificate. The banner says so and links straight to your hub, so you can accept it and come back. Each phone, tablet and computer has to do this once.
- **Hestia loaded over `https://` with an `http://` hub address:** the browser is blocking the connection as insecure. The banner explains that and points at the `:8443` address.
- **Anything else:** the familiar reminder to check the hub is powered on and on the same network.

## Keyboard and screen-reader access

Most of Hestia's controls were built in a way that looked and clicked like buttons without actually being buttons. If you navigate by keyboard or use a screen reader, most of Settings was unreachable: you could not tab to a section, and a screen reader announced very little of it.

This is now fixed across the app rather than control by control.

- Every clickable element can be reached with Tab and activated with Enter or Space.
- Screen readers announce what each control is and what it does, including the toggle switches, which previously had no name at all.
- Settings behaves as a proper dialog: focus moves into it when it opens and back to where you were when it closes, Tab stays inside it, and Escape closes it. The same goes for the PIN prompt.
- Every settings field is properly tied to its label, collapsible sections announce whether they are open, and decorative icons are no longer read aloud.
- A visible focus outline appears for keyboard users only. Nothing changes if you use a mouse or touch.

Verified with the browser's own accessibility tooling and by keyboard. A pass with a real screen reader is still planned.

## Why this is its own version

These fixes first shipped as an update to v1.6.7. That reaches hestari.com immediately, but **not** dashboards served from your hub: Hubitat Package Manager only compares version numbers, so an unchanged version means no update is offered and no new copy is downloaded. Bumping to v1.6.8 is what actually delivers the above to hub-served installs.

## Updating

- **hestari.com:** nothing to do.
- **Hub-served:** update through Hubitat Package Manager as usual. The companion app version moves to 1.6.8 as part of this; its code is otherwise unchanged from v1.6.7.

## Also in this release

- Corrected an internal note about how the Ring integration reports its countdown, confirmed against real hub logs.
- Focus handling no longer relies on a browser callback that never runs while a tab is in the background, which matters for always-on wall panels.
