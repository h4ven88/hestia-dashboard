# Hestia v1.6.9 (and v1.6.8) — Garage doors, and a keyboard/screen-reader pass

Two releases landed close together, so here they are in one go.

## Garage doors (v1.6.9)

Hestia now treats a garage door as a garage door. Before this it had no concept of one, so if you added an opener it was stored as a light switch.

That had a real consequence worth knowing about: it counted as a light, which meant **"all lights on" or "all lights off" sent it an on/off command**. On a relay-style opener, which is most Hubitat garage setups, `on` is the command that moves the door. If you have a garage door in Hestia, this release is the one to take.

What you get now:

- A control in **Security, under your locks**, and in its room if you've assigned one. Both stay in sync.
- Real states: Closed, Open, Opening, Closing, or Unknown, with the panel in the icon travelling up or down while the door is actually moving.
- **Closing is one tap. Opening asks first**, with a confirm button that expires after five seconds. By voice, closing is immediate and opening waits for a spoken "yes", because a wake word can be set off by a TV or someone outside a window. Routines can close a garage but never open one, since a routine can run with nobody home.
- It drives your hardware the way it expects: proper garage devices get open/close, relays get a pulse, momentary openers get push. Openers that use a single pulse for both directions confirm in both directions and show one honest "Move door" button.
- It won't claim a door is shut when it isn't. If your hub reports an unknown state, or a driver gets stuck reporting "opening" (a known Hubitat quirk), you get Unknown rather than a comfortable lie.

Detection works by capability for any brand. Relay openers don't advertise a garage capability at all, so those are matched on a name containing "garage" plus door/opener, and anything missed can be set by hand in Settings, which now lists Garage Door as a device type. If you already had one saved as a switch, it moves out of your lights automatically, but only when the device's own capabilities prove it is a door. A switch named "garage light" stays exactly where it is.

**myQ owners:** Chamberlain closed their API to third parties back in 2023, which is why the Hubitat integrations stopped working. There's no safe way around it from Hestia's side, and I'm not going to ask anyone to store their Chamberlain password to try. Local hardware like ratgdo or the Konnected GDO blaQ replaces the cloud path and shows up as an ordinary Hubitat device, which Hestia then picks up on its own. Check your opener's learn button first: white means Security+ 3.0, which ratgdo doesn't support.

## Keyboard and screen reader support (v1.6.8)

If you navigate by keyboard or use a screen reader, most of Settings was unreachable. Every clickable element can now be reached with Tab and activated with Enter or Space, Settings behaves as a proper dialog (focus moves in and back out, Escape closes it), fields are tied to their labels, and the toggles announce themselves. A visible focus outline appears for keyboard users only, so nothing changes if you use a mouse or touch.

## Exit delay, and a clearer "Hub unreachable" (v1.6.8)

The arming countdown now agrees with itself everywhere. The mode row highlights the mode you're arming into instead of leaving Disarm lit, and the card, sidebar, topbar and Home screen all show the same ticking countdown, so leaving the Security screen no longer loses it.

The "Hub unreachable" banner also names the likely cause instead of one generic line. On an HTTPS hub address it points out that this device may not have accepted the hub's certificate yet, with a link to go do it. Each phone, tablet and computer needs that once.
