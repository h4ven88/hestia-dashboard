# Hestia v1.6.3 Release Notes

**Release Date:** 2026-09-01

---

## Push Notifications: actually working now, end to end

v1.6.2 shipped the Push Notifications settings UI and Cloudflare backend, but the actual trigger mechanism didn't work reliably. This release replaces it with one that does, confirmed on both desktop and mobile.

**What changed under the hood:**

- **New trigger: Maker API's own device-event webhook**, not hub-side polling. The Hubitat companion app previously tried to poll Maker API for device changes, but a Groovy app running on the hub can't reliably make outbound HTTP calls back to its own hub — that's a fundamentally different (and sometimes blocked) network path than any other device reaching the hub. Maker API has a built-in answer instead: a "POST URL" field that streams every device event to a URL in real time, using devices already authorized for that exact Maker API instance. Hestia now registers this automatically the moment Push Notifications is turned on — no manual setup, no re-selecting devices anywhere.
- **Arm-state and the alarm category still come from the Hubitat app directly**, via a native HSM subscription that was never affected by the polling issue above — it's an internal event subscription, not a network call.
- **Fixed a real encryption bug in the Cloudflare backend.** The cloud config sync is end-to-end encrypted (AES-GCM, keyed by your household's own public IP — nobody but your own devices can read it, including us). The backend was reading that encrypted blob incorrectly, silently getting empty data back on every check instead of an error. This is why push kept reporting "disabled" even when it was clearly on.
- **Fixed a cross-device sync race.** Toggling Announcements or Push on one device could silently get overwritten by another device's stale save moments later, including a boot-time ordering bug that could push outdated settings to the cloud before your device's changes were even applied, and a save that fired 100ms into every page load — before syncing with the hub — that could win a timing race against the correct data on every single reload.
- **Better error messages when push subscription fails.** Brave's browser-level "Use Google services for push messaging" setting (found under `brave://settings/privacy`) can silently block push notifications; Hestia now detects this specific failure and names the setting directly instead of a generic "try again."

### You need to update the Groovy app for this to work

Unlike the dashboard file, the companion app's own source code has no auto-update mechanism on Hubitat unless it was installed through Hubitat Package Manager. If you installed it by pasting the code directly into Apps Code:

1. Open **Apps Code** on your hub, find **Hestia Dashboard**.
2. Replace the contents with the latest `HestiaDashboard.groovy` from the [GitHub repo](https://github.com/h4ven88/hestia-dashboard/blob/main/HestiaDashboard.groovy).
3. Save, then open the Hestia app instance and click **Done** once to re-initialize it.

If you installed via HPM, this update will show up as an available update the normal way.

If you already updated the Groovy app for v1.6.2, you still need to do this again — the trigger mechanism changed significantly since then.
