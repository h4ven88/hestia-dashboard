# v2.1.1 forum post

**v2.1.1 is up. If you set a reminder in the evening yesterday, it went in on the wrong day.**

Every place Hestia wrote down a date used the UTC date instead of your local one. Those agree for most of the day and disagree for the rest — west of UTC all evening, east of UTC all early morning. In New York, from 8 PM, "today" quietly became tomorrow.

So picking **Once (today)** at 8:35 PM saved it for the next day. The list then correctly said "Tomorrow at 8:35 PM", which made it look like the app was arguing with itself. The same mistake in reverse hid a reminder created at 8:42 PM from *today's* calendar row.

Both fixed, along with the reminder date picker, the calendar's own day cells, and the date Athena gets when you set one by voice. The calendar squares were also drawing one-time reminders a day early everywhere east of UTC, which New York could never show.

**Two other things in this one:**

The inline **Add Reminder** form on the home screen now refuses a time that has already gone by today. v2.1.0 added that to Settings and missed this form, and it could not be reached there anyway while "today" was always tomorrow.

Reminders that have run out now say **Finished** instead of sitting under Active Reminders reading "No upcoming fire". Edit gives one a new schedule, Delete removes it, nothing is removed for you. One you switched **off** is paused, not finished, and stays where it was.

**What you need to do.** Recurring reminders fix themselves — the hub's queue is rebuilt from scratch on every sync. A one-time reminder created during an evening is still saved a day late, and only you know whether you meant that day, so Hestia will not rewrite it: Settings → Reminders → Edit, and set the date you wanted.

**Updating.** Paste `HestiaDashboard.groovy` over Apps Code → Save, open the Hestia app, click **⬇ Update Dashboard File**, then reload. The Groovy itself is unchanged here; its version moves with the dashboard so the two never look out of step. The footer should read v2.1.1.
