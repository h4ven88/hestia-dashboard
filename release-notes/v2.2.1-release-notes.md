# Hestia v2.2.1 — security fix: the disarm PIN

**Update as soon as you can.** This release fixes a defect that could leave a
household's Artemis disarm PIN silently unset, in which case the keypad still
appeared, still said "Enter PIN to disarm", and accepted **any** digits.

Found because a user typed a wrong PIN and the house disarmed.

---

## ⚠ Check this first

Open **Settings → Diagnostics → Run all checks** and look at the new
**Disarm PIN** row.

- **"PIN required to disarm"** — you are fine.
- **"No PIN set — anyone can disarm Artemis"** — set one again in
  **Settings → Artemis → Security PIN**. It cannot be recovered; PINs are stored
  as hashes and the stored value was replaced with an empty one.

Artemis now also shows a red warning on the Security screen and on the mobile
PIN sheet whenever no PIN is set, so this state can never again look like a
working PIN.

## How to update

1. Update **Hestia Dashboard** in Hubitat Package Manager, or copy
   `HestiaDashboard.groovy` into **Apps Code** and Save.
2. Open the Hestia app and click **⬇ Update Dashboard File**.
3. `initialize()` is unchanged in this release, so **Done is not required**.

The companion app must be updated: the most important guard in this release
lives on the hub, and it protects you even from dashboards that are never
updated.

---

## What went wrong

Three separate defects lined up.

**1. A device could publish an empty configuration over the household's real
one.** When a device has no saved settings of its own, boot asks the hub for the
household config. That request returns "nothing" for *every* kind of failure — a
timeout, a dropped connection, a backed-off companion app — and boot could not
tell those apart from "this hub genuinely has no configuration yet". On
"nothing", it saved its own settings to the hub and the cloud so other devices
could pick them up. But a device with no settings has **defaults**, and defaults
contain an empty PIN, an empty PIN salt and empty everything else. One transient
read failure was enough to overwrite the household record, after which every
other device loaded the blank copy.

**2. Nothing refused the blank.** Both the dashboard and the companion app
applied an incoming configuration as-is. The companion app already protected the
household encryption key this way; the PIN fields had no equivalent.

**3. With no PIN stored, the keypad accepted anything — and said nothing.**
Allowing any entry when no PIN is set is deliberate, so a household that chooses
to run without one is not locked out of its own house. The defect was that it
was invisible: the prompt was identical either way.

## What changed

- Boot can now tell "the hub has no configuration" from "the hub did not
  answer", and **only ever writes in the first case**. In the second it shows a
  screen saying so, with a retry, and changes nothing.
- An incoming configuration can no longer clear a PIN this device holds. A
  deliberate **Remove PIN** still works: removals carry a change stamp, and a
  device that simply never had a PIN does not.
- The PIN salt is never cleared at all. Every stored PIN hash is derived from
  it, so losing it would orphan both PINs at once.
- **The companion app enforces the same rule at the hub.** This is the one place
  every device must pass through, so it holds even for old dashboards that will
  never be updated. It is best-effort and can never reject a save.
- Artemis states plainly when no PIN is set: a red warning on the Security
  screen and the mobile PIN sheet, an honest keypad label, and a new Diagnostics
  check.
- Fixed a long-standing cosmetic bug: the mobile PIN sheet read
  "Disarming — Armed Armed · Home".

## Verification

820 tests across 15 suites, including a new suite dedicated to this area that
runs the real shipped functions. Mutation gate: 18 of 18 on the dashboard
changes and 9 of 9 on the companion app, meaning every one of those fixes was
deliberately broken in the real source and the suite went red each time.

Verified on a real household: the new warning, keypad label, PIN sheet and
Diagnostics check all behave as described on a device with no PIN set.
